# The map's string hash, FNV-1a against eight bytes at a time (2026-11-10)

`MapHash` of a string was FNV-1a over the bytes. `string-hash` reads eight bytes at a time (the last word
overlapping; two overlapping four-byte words for 4 to 7 bytes; the length in the seed; a multiply and a
shift finalizer) where unaligned words are safe, and keeps FNV-1a below four bytes and elsewhere. A map's
iteration order is the entry arrays' order (insertion), not the slots', so no hash changes what a program
sees. `tools/map-hash-study.py` (a one-off script, removed with the repository's Python: see git history at a8e65b35) modeled the runtime's table (power-of-two slots, linear probing, growth at
half full) and measures, for each key set, the mean probes of a successful lookup, the longest probe, and the
longest run of occupied slots, and the "marks" count: probes that passed a slot whose mark (the hash's
upper bits, which the table compares before touching the key) equals the probing key's, so a key compare was
spent for nothing:

The new hash behaves like a random one (mean about 1.3 probes at the table's load): it matches FNV-1a on
unstructured keys and loses where FNV-1a happens to place keys that differ only in their last byte or two
next to each other (prefix + 1 to 3 bytes: mean 1.44, 1.23, 1.27 against 1.00, 1.03, 1.23; the sequential
numeric strings: mean 1.46 and longest probe 42 against 1.41 and 25). No key set shows a pathological run.
Instructions: a map of 200k distinct string keys -8.7% (cycles -2.7%), the `maps` benchmark -1.9%, the
compiler's own self-build -0.2%.

The marks are the upper 32 bits of the hash outside the slot's mask, the slot the low bits, so the two use
different bits of the same hash: with the new finalizer the false marks stay at a few per hundred thousand
keys (902 among the probes of a million sequential numbers, against 30 for FNV-1a; at most 9 elsewhere), so
the mark filter still saves almost every key compare. Neither hash is seeded, so neither is hard to attack
with chosen keys; a seeded hash is the step if a server's map is ever keyed by untrusted strings.
